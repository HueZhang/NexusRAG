## 一、项目全景类

**Q：介绍一下你的这个项目？**
> A：（电梯陈述）NexusRAG 是一个通用 RAG 中台。核心层只面向接口——大模型、向量库、
> 切分器都能替换；上面用适配器接入不同行业知识库，医疗说明书合规问答是第一个落地模板。
> 我做这个是为了解决一个实际问题：RAG 落地时最大的坑不是"能不能跑通"，而是"效果好不好、
> 怎么量化"。所以我特别看重数据管道和评测两块。

## 二、技术选型 / 为什么这么做

**Q：为什么用 Python 不用 Java？**
> A：RAG 的瓶颈其实不在语言性能——单次请求大头是大模型生成的 IO 等待，Python 的 GIL
> 在这里不是瓶颈；真正的并发压力在检索和文档摄取，那部分用异步和批处理解决。
> 而且 RAG 生态 Python 最全、岗位最多。Java 我也能写业务接口，团队是 Java 栈我能快速上手。

**Q：为什么做中台，不直接做个应用？**
> A：因为"换行业只换模板"能体现架构能力，也是这个岗位真正需要的——企业要的是能复用的落地平台，
> 不是一个 demo。（细讲 ADR-000）

## 三、评测 / 效果类（重点，多准备）

**Q：你怎么衡量 RAG 效果好不好？**
> A：用 RAGAS 那套三角指标：检索的 Context Relevance、生成的 Faithfulness（防幻觉）、
> 以及 Answer Relevance。每一层单独度量，才知道问题出在检索还是生成。

**Q：怎么防幻觉？**
> A：三层——检索层保证有据可查、生成层要求"只依据检索内容回答并给出引用"、
> 检索不足时明确拒答而不是编造；评测层用 Faithfulness 指标持续监控。

## 四、行为 / 短板类

**Q：你是二本 / 之前没做过 AI，为什么觉得能胜任？**
> A：（诚实 + 证据）学历不假，但我用可演示的项目补：能打开就用的 Demo、量化的评测结果、

> RAG 落地拼的是"把不稳的东西做稳、把效果量化"，这是我的强项。
