## 1. 背景与目标

**背景**：开发者原为 C# / 医院项目背景，计划转向 AI Agent / RAG 应用岗。
C# 直接相关的 Agent 岗位极少（市场统计仅约 2%），故技能重心转向 Python + RAG 应用落地。

**目标**：用 3–4 个月（在职业余）打造一个**能证明"我具备 RAG 应用落地能力"**的作品，
以项目成果弥补"二本学历 + 无 AI 项目经验"的简历短板，主投上海 RAG / AI 应用岗。

**目标岗位画像**：AI 应用工程师 / RAG 工程师 / LLM 应用开发（应用侧，**非算法侧**）。

## 2. 项目定位

NexusRAG 是一个**通用 RAG 中台**，核心能力与行业解耦：

- **通用中台 = 核心**：数据管道 + 检索 + 生成 + 评测，四层一体。
- **场景模板 = 可插拔**：医疗说明书合规问答作为**首个落地模板**，验证"中台可复用"。
- 一句卖点：*"A platform to forge RAG pipelines for different domains."*

> 差异化：不拼算法、不拼名校，拼**能把 RAG 稳定接进真实业务并量化效果**——
> 后端工程功底 + 领域知识，是这个岗位真正的护城河。

## 3. 四层架构

```
┌───────────────────────────────────────────────┐
│ 接入层 Adapters（场景模板）                       │  医疗说明书 / 后续…
│   每个模板 = 专属解析器 + Prompt 模板 + 评测集      │
├───────────────────────────────────────────────┤
│ 应用层 Application（Pipeline 编排）               │  检索 → 重排 → 生成 → 引用
├───────────────────────────────────────────────┤
│ 核心层 Domain（只定义接口/协议，无实现）            │  LLMProvider / Embedder /
│                                                  │  Retriever / Reranker / Chunker
├───────────────────────────────────────────────┤
│ 基础设施层 Infrastructure（实现核心层接口）         │  DeepSeek/通义/Ollama 适配器,
│                                                  │  Chroma/pgvector, BGE reranker…
└───────────────────────────────────────────────┘
        ↑ 数据管道（Ingestion） & 评测（Evaluation）贯穿全程
```

**设计原则**：
- 核心层**只依赖接口**，不依赖具体模型 / 向量库 / 行业。
- 换 LLM、换向量库、加新行业 = 替换基础设施层或新增 Adapter，核心不动。
- 评测不是终点，而是贯穿每一环节的质量标尺。

## 4. 里程碑与验收标准（Definition of Done）

> 每个里程碑必须产出**可演示 / 可截图 / 可量化**的成果，防止埋头写码无展示物。

| 里程碑 | 内容 | 验收标准 (DoD) |
|---|---|---|
| **M0 脚手架** | 目录、文档体系、git 规范 | 仓库初始化，文档骨架齐全，首次提交完成 |
| **M1 最小闭环** | 单文档 → 切分 → 向量检索 → 带引用问答 | 对一个 PDF 能问答并显示原文出处，录 30s 演示 |
| **M2 数据管道** | 批量摄入、清洗、PDF 表格/去噪、增量更新 | 100+ 文档批量入库，可增量更新，摄取有日志 |
| **M3 检索增强** | 混合检索（BM25+向量）、Rerank、多路召回 | 相对 M1，检索召回率有量化提升（写入 JOURNAL） |
| **M4 评测体系** | RAGAS 式评测：Context Relevance / Faithfulness / Answer Relevance | 有 eval 集与自动评测脚本，产出指标报告 |
| **M5 医疗模板** | 说明书语料 + 医疗 Prompt + 医疗评测集 | 医疗说明书合规问答可用，答不出会拒答，带引用 |
| **M6 平台化收尾** | 多知识库配置、README/文档完善、Demo 部署 | 可切换不同知识库；GitHub README 完整可展示 |

## 5. 数据源（公开、合规）

- **大医网 dayi.org.cn**：药品说明书 / 适应症 / 用法用量（文档级）
- **NMPA 国家药监局数据查询**：药品 / 器械基础数据（结构化字段）
- **评测集**：从公开中文医疗 QA 数据集参考 + 基于说明书**人工构建**问答对（体现用心）

红线：不碰患者病历/处方等隐私，不绕过登录/付费墙，礼貌限速。

## 6. 技术栈

- 主：**Python**（RAG 主链路、服务）。适配层设计，可切换多家 LLM API 与本地模型（如 Ollama）。
- 向量库：Chroma（起步）/ pgvector（进阶）；Embedding：BGE 类；Rerank：BGE reranker。
- 评测：RAGAS 思路自研或复用。
- 其他语言（如 Java）仅在确有需要时引入，且优先于 C#（岗位现实）。
