## 1. RAG 全景（动手前扫一眼，建立整体图）

### RAG 是什么、为什么需要它
LLM 有三个天生缺陷：**① 会一本正经地胡说（幻觉）② 知识有截止日期（不知道最新）③ 不知道你的私有数据**。
RAG（检索增强生成）= 让 LLM 回答前**先去你的资料库里查资料**，看着查到的内容回答，并给出出处。
一句话：**RAG = 开卷考试。LLM 是考生，向量库是课本，检索是翻书，回答是答卷。**

### 全流程一张图
```
① 采集(已有1000份) → ② 清洗 → ③ 切分 → ④ 向量化 → ⑤ 入库
                                                      ↓
用户提问 → 向量化 → 在向量库按"意思"检索 top-k 张卡片 → (可选:重排)
                                                      ↓
                           问题 + 检索到的卡片 → 拼成 Prompt → 调 LLM → 带引用回答
                                                      ↓
                                              ⑥ 评测：答得好不好？有依据吗？
```

### 四个核心概念（大白话，后面里程碑会展开）
| 概念 | 一句话 | 比喻 |
|---|---|---|
| **切分 Chunking** | 把长文档切成小段（卡片） | 把厚书撕成一张张知识卡片 |
| **向量化 Embedding** | 把文字变成一串数字（语义指纹） | 给每张卡片编一个"意思指纹" |
| **向量库 Vector DB** | 按"意思相似"搜索的数据库 | 一个会自动按内容归类的卡片柜 |
| **LLM 大模型** | 看着检索到的卡片写答案 | 考生翻着书答题 |

### 🟨 M1 数据管道：清洗与切分（← 当前在这里）
> 这是整个项目最容易被低估、却最影响效果的一步。别急着跑问答，先打好底座。

- **做什么**：
  - 统一两类数据（化学药/中成药 vs 中药材）的不同字段到**统一 schema**
  - 清洗：去空值、合并同义字段（"适应症"≈"适应病症"、"主要功效"≈"功效作用"）
  - **按章节切分**：一药一章一节 = 一张卡片（chunk），每张卡片带 `drug_name + 章节名 + 出处url`
  - 产出：`data/processed/chunks.jsonl`（每行一张卡片）
  - **顺带**：从说明书自动抽一批"问题+答案+出处"候选，生成评测集初稿 `data/eval/medical_qa_dev.jsonl`（人工再修正）
- **学什么**：
  - 结构化数据清洗（字段映射、缺失值、同义合并）
  - **Chunking 切分策略**：按固定字数 / 按段落 / 按语义 / 按章节——各自优缺点
  - **token 是什么**：模型处理文本的最小单位，切分为什么要考虑它（太大塞不下、太小丢上下文）
  - 切分粒度权衡：卡片太大→检索不准；太小→上下文断裂
- **自检**：
  - 为什么要切分？不切直接喂给模型不行吗？
  - 按章节切 vs 按固定字数切，对你的说明书为什么章节切更好？
  - 一张卡片太大或太小分别会出什么问题？

---

### ⬜ M2 向量化与入库
- **做什么**：
  - 选 Embedding 模型（默认 `bge-m3`，中文强、免费、本地跑）
  - 把 M1 的每张卡片向量化
  - 建 **Chroma** 向量库，把"卡片+指纹+元数据(drug_name/章节/url)"存进去
- **学什么**：
  - **Embedding 原理**：文字 → 高维向量（一串数字），意思相近则向量相近
  - **余弦相似度**：怎么算两个向量"像不像"（0~1，越接近1越像）
  - 向量库 vs 传统数据库：一个按"精确值"查，一个按"语义相似"查
  - 为什么你的量级（约1万张卡片）Chroma 就够
- **自检**：
  - Embedding 到底把文字变成了什么？为什么能用它做语义搜索？
  - 用户问"婴儿能吃吗"，系统怎么找到"适应病症：婴儿佝偻病"那张卡的？
  - 向量库和 MySQL 的本质区别是什么？

---

### ⬜ M3 检索与生成（最小闭环跑通 ← 第一个能演示的成果！）
- **做什么**：
  - 用户提问 → 向量化 → 向量库检索 top-k 相关卡片 → 拼 Prompt（问题+卡片）→ 调 LLM → 输出**带引用的回答**
  - 默认 LLM：DeepSeek（便宜、中文强）；也可接本地 Ollama
  - 跑通后**录 30 秒演示**（这是你简历第一个可展示物）
- **学什么**：
  - **top-k**：检索最相关的 k 张卡片（k 太大噪音多、太小漏信息）
  - **Prompt 工程**：怎么组织"角色+约束+检索材料+问题"，让模型只依据材料回答
  - **引用溯源**：回答里标明"[出处：X药说明书-用法用量]"——医疗场景刚需
  - **防幻觉**：检索不到就明确说"资料中未提及"，别编
- **自检**：
  - top-k 怎么选？调大调小分别什么后果？
  - 检索到的卡片和问题无关时，怎么保证模型不乱答？
  - 引用/出处为什么在医疗场景特别重要？

---

### ⬜ M4 检索增强（效果进阶）
- **做什么**：
  - **混合检索**：向量检索（懂语义）+ BM25（懂关键词）结合
  - **Rerank 重排**：用 Reranker 模型对初检结果再精排
  - 对比 M3，量化"召回率/准确率"提升（写进 JOURNAL）
- **学什么**：
  - **BM25**：传统关键词检索算法（TF-IDF 家族），强在精确词匹配
  - 向量检索的短板：对"专有名词/型号/缩写"可能不敏感 → 所以要 BM25 补
  - **Reranker**：把"粗筛"出的候选再用更精细的模型排序
  - **召回率 Recall**：真正相关的资料，被检索出来多少
- **自检**：
  - 既然向量检索很强，为什么还要 BM25？
  - Rerank 和初次检索的区别是什么？为什么分两步？
  - 你怎么证明 M4 比 M3 效果好？（→ 引出 M5）

---

### ⬜ M5 评测体系（专业 vs 业余的分水岭）
- **做什么**：
  - 完善评测集（M1 初稿 + 人工修正，扩到 80–100 条）
  - 写自动评测脚本，按 **RAGAS 三角**打分
  - 产出指标报告（如"Context Relevance 0.85 / Faithfulness 0.9 / Answer Relevance 0.82"）
- **学什么**：
  - **RAGAS 三角**：
    - **Context Relevance**：检索到的上下文和问题相关吗？（评检索）
    - **Faithfulness**：答案是否忠于检索内容？（防幻觉）
    - **Answer Relevance**：答案是否回答了问题？（评生成）
  - 评测集怎么构建：问题+参考答案+出处
  - 为什么"能 demo"和"能量化效果"是业余和专业的分水岭
- **自检**：
  - 怎么衡量 RAG 答得好不好？三个指标分别管什么？
  - 幻觉怎么量化？Faithfulness 低说明哪一层出问题？
  - 你项目里最好的一个数字是什么？它怎么来的？

## 3. 概念速查表（Glossary）

| 术语 | 一句话解释 | 首次出现 |
|---|---|---|
| RAG | 检索增强生成，让 LLM 开卷答题 | 全景 |
| Chunking | 把长文档切成小卡片 | M1 |
| token | 模型处理文本的最小单位 | M1 |
| Embedding | 把文字变成语义向量（指纹） | M2 |
| 余弦相似度 | 算两个向量有多像（0~1） | M2 |
| 向量库 | 按语义相似搜索的数据库（Chroma等） | M2 |
| top-k | 检索最相关的 k 条 | M3 |
| Prompt 工程 | 组织输入让模型按预期回答 | M3 |
| 引用溯源 | 回答标出处 | M3 |
| 防幻觉 | 没依据就说不知道，不编造 | M3 |
| BM25 | 传统关键词检索算法 | M4 |
| Reranker | 对候选结果再精排的模型 | M4 |
| 召回率 Recall | 相关资料被找回的比例 | M4 |
| RAGAS | RAG 评测框架/三角指标 | M5 |
| Context Relevance | 检索上下文与问题的相关性 | M5 |
| Faithfulness | 答案忠于检索内容的程度 | M5 |
| Answer Relevance | 答案切题程度 | M5 |
| 适配器模式 | 核心定接口、场景做插件的架构 | M6 |
